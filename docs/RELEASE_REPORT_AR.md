# رواق | تقرير الإصلاح والتشغيل التجريبي

تاريخ العمل: 6 نوفمبر 2026. الحالة: نسخة اختبار بخدمات خلفية، وليست متجرا جاهزا للبيع الفعلي.

## ما أعيد إنتاجه قبل التعديل

أكد الفحص السابق حقن أوامر من رابط التصنيف، وتعطل JSON السلة والمنتج غير المعروف، وتعطل ترميز الرابط، وقبول 1.5 عبوة، وإجمالي سالب عند تغيير السلة المحلية، وبطاقات تعرض سعر 250 جم مع فلتر الكيلو، وظهور كيلو إثيوبيا غير المتوفر، وتكرار نفس الخيار عند تعديله، وترتيب أحدث غير مبني على تواريخ. أثبت اختبار الحقن غير الضار تغيير عنوان الصفحة فقط. لم تختبر خدمات دفع حقيقية أو بنية الاستضافة ضمن ذلك الفحص.

## نتيجة الإصلاح

| النتائج | المعالجة | الدليل |
|---|---|---|
| SEC-01 | مسارات وتصنيفات مسموحة، إزالة معالجات الأحداث النصية، ربط أحداث ثابت، هروب النصوص، CSP دون unsafe-inline أو unsafe-eval للسكربت | اختبار المسارات + فحص المصدر + تجربة الرابط القديم في المتصفح |
| REL-01 / REL-02 | قراءة السلة ضمن معالجة أخطاء، التحقق من الخيارات والكميات، إصلاح وإشعار المستخدم، ترحيل السلة القديمة | اختبار الاستعادة وترحيل صيغة السلة |
| REL-03 | تحليل آمن للمسارات والترميز، صفحة غير موجودة | اختبارات روابط تالفة |
| CART-01 / CART-03 | أعداد صحيحة موجبة فقط، أسعار صحيحة بالهللات، الخادم يعيد حساب الطلب ولا يقبل السعر القادم من المتصفح | اختبارات كميات وأسعار مزورة |
| CART-02 | الدمج حسب variant_id، تجميع استهلاك المخزون عبر خيارات الطحن، حجز ذري في قاعدة البيانات | اختبارات دمج وفشل ذري وفحص إعادة التحقق عند الإدخال |
| CAT-01 / CAT-02 | الفلتر والبطاقة والرابط يستخدمون الوزن والسعر والتوفر نفسيهما | اختبار الكيلو والمتصفح: البرازيل 165.60 ريال، وإخفاء كيلو إثيوبيا |
| CAT-03 | created_at وترتيب زمني فعلي، فلاتر داخل الرابط | اختبار أحدث منتج وروابط الفلاتر |

## ما أضيف

- ترحيل من ملفات عرض ثابتة إلى Vinext/Workers مع قاعدة D1 ومخطط وترحيل SQL محفوظين.
- جداول منتجات وخيارات ومخزون وعملاء وطلبات وسطـور طلب وأحداث دفع تجريبية وسجل إدارة وصندوق رسائل غير مفعل.
- قراءة المنتجات وتحديد الأسعار من الخادم، مع تخزين متصفح للسلة واللغة فقط.
- إنشاء طلبات sandbox وحجز المخزون 30 دقيقة. تنتهي الحجوزات عند أول استدعاء مناسب للخادم بعد الانتهاء؛ لا توجد مهمة خلفية دورية حاليا.
- مفاتيح منع تكرار الطلبات، ومعاملات حجز تعود بالكامل عند الفشل، وقيود SQL تمنع المخزون السالب وتعيد فحص التوفر والسعر.
- إيصال طلب محمي برمز عشوائي لا يوضع في الرابط. إلغاء طلب الاختبار وإعادة المحاولة متاحان لصاحب الرمز.
- إدارة محمية على الخادم بهوية المنصة وبريد المسؤول المضبوط خارج المصدر: إنشاء منتجات، تعديل الأسماء والصورة كرابط HTTPS والأسعار والمخزون، إخفاء المنتجات، الطلبات، سجل الإدارة.
- محاكاة أحداث دفع للمسؤول فقط: نجاح، فشل، إلغاء، استرداد؛ لا تحصيل حقيقي. الأحداث المكررة لا تنفذ مرتين. الاسترداد لا يعيد المخزون تلقائيا لأن قرار إعادة التخزين يحتاج فحص السلعة.
- حماية Origin لطلبات الكتابة، حد لحجم جسم الطلب، تحديد معدل، وعدم تسجيل بيانات العميل في سجلات الأخطاء.
- تصدير احتياطي محمي، وأداة استعادة غير متصلة إلى قاعدة جديدة فقط، مع فحص سلامة ومرجعيات.
- إزالة نموذج الاشتراك غير المتصل بدلا من الإيحاء بعمله.

## الاختبارات وحدودها

19 مجموعة اختبارات آلية ناجحة: راجع tests/commerce.test.mjs وdocs/test-results.txt. تستخدم SQLite مع واجهة تحاكي D1 لاختبار المنطق والمعاملات والقيود. نجح بناء الإنتاج وفحص TypeScript.

اختبارات المتصفح على معاينة مرتبطة بقاعدة D1 محلية: عرض المنتجات، فلتر الكيلو وأسعاره، رفض كمية كسرية، إضافة للسلة، عرض سعر الخادم، حفظ طلب اختبار برقم مرجعي، استعادته بعد تحديث الصفحة، وإلغاؤه. راجعنا عرض قائمة المنتجات والفلاتر بعرض الجوال بالعربية والإنجليزية دون تمرير أفقي. تحفظ قاعدة المعاينة بيانات تجريبية فقط، ولا تنسخ مع قاعدة الإنتاج.

حدود يجب مراعاتها: ليست اختبارات اختراق شاملة أو حمل موزع. اختبارات الدفع هي محاكاة لمنطق الحالات وليست تكاملا مع مزود دفع. صلاحيات الإدارة اختبرت آليا عند واجهة الخادم؛ واجهة المسؤول المستضافة تحتاج مرور المالك عبر تسجيل الدخول. يجب التحقق من ترويسات CSP على عنوان الإنتاج بعد النشر بصلاحية مناسبة. لا توجد اختبارات بوابة دفع أو شركة شحن فعلية أو فواتير ضريبية.

## قرار البنية

استمررنا على الاستضافة القائمة مع Workers وD1 للحفاظ على الهوية والموقع وإصلاحه وإتاحة اختبار الخادم. لم نفترض ميزانية أو حجم مبيعات غير معطى. لإطلاق تجاري محدود الفريق، ينبغي مقارنة تكلفة تشغيل هذا الحل وصيانته مع منصة تجارة جاهزة تدير الدفع والشحن والفواتير؛ لا يلزم الانتقال لإغلاق الأخطاء الحالية، لكن القرار مطلوب قبل دفع تكلفة تكاملات مخصصة.

## الموانع المتبقية قبل البيع

1. اختيار مزود الدفع والشحن والبريد، وتوفير حسابات اختبار وحسابات تاجر مؤهلة ومفاتيحها عبر قناة أسرار معتمدة. لا ترسل المفاتيح داخل المصدر.
2. كتابة محولات المزودين المحددين واختبار الإشعارات الموثقة والتوقيع/آلية التحقق المعتمدة، والمبلغ والعملة والطلب ومعرف الحدث قبل اعتماد الدفع.
3. ربط الشحن والتتبع والرسائل. الصندوق الحالي يسجل الرسائل بحالة blocked_config ولا يرسلها؛ ليس نظام تسليم مفعل.
4. إعداد الضرائب والفوترة وفق بيانات المنشأة، ومراجعة الشروط والخصوصية والاحتفاظ والحذف.
5. استبدال البيانات الافتراضية بمنتجات وصور وأسعار ومخزون وبيانات تواصل حقيقية.
6. تفعيل مراقبة وتنبيهات تشغيلية ونسخ احتياطية خارجية دورية، وتجربة استعادة من البيئة المستضافة في بيئة منفصلة. نجحت الاستعادة محليا فقط.
7. اختبارات حمل وتزامن على البيئة المستضافة، ومراجعة أمن مستقلة، وتجربة المسار الكامل باللغتين وعلى أجهزة فعلية، ومراجعة SEO لروابط hash قبل فهرسة متجر عام.
8. اعتماد خطة إطلاق وعنوان تجاري وجمهور الموقع. ما زالت صلاحية الموقع خاصة بالمالك؛ لم تفتح للعامة.

الدفع والشحن والاشتراك تفشل برسالة غير مفعل؛ لا يوجد مفتاح إعداد يحول النسخة تلقائيا إلى تحصيل فعلي.
